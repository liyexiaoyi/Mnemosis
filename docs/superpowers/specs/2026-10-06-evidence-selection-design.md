## 1. 目标、用户意图与首版范围

用户希望继续优化数学模型，优先检索准确与必要证据完整，保留仿生设计，并让不同公式负责不同部分。延续上次提出、用户要求继续推进的方向：先独立、只读、显式问题要点的证据选择，再考虑接入检索。

本设计把工作记忆作为“有限容量下挑选互补线索”的职责；BM25、余弦、RRF、联想、遗忘、verified Beta及已修的旧校准诊断保持各自职责。工作记忆选择的分数不是事实真实性、答案正确率或脑机制的生理模拟。

首版只新增一个无存储依赖的Python模块与测试/离线诊断；调用方显式提供候选ID、已归一化相关性和固定支持矩阵。没有自动要点抽取、模型调用、事实版本迁移、语义合并、语言迁移、MCP/CLI入口、自动访问强化或默认检索切换。现有working_set按最近访问排序，working_set_budget统计容量，二者保持。

## 2. 方法选择

建议采用非负相关性加饱和要点覆盖：重复支持同一要点主要不再增加覆盖，新要点获得新增价值，可返回逐步选择理由。需明确提供独立问题要点，支持矩阵质量决定代理目标的意义。

备选MMR把相关性减去与已选项的最大相似度，适合减少相似内容；相似记忆也可能是必要时间链，负惩罚与本方案的单调覆盖目标不同。原TopK作为回归/对照，接口稳定，但没有显式互补覆盖目标。[Carbonell与Goldstein的MMR原文](https://www.cs.cmu.edu/afs/cs/Web/People/jgc/publication/MMR_DiversityBased_Reranking_SIGIR_1998.pdf)。首版数学验收不依赖接入嵌入模型或新增MMR产品策略。

## 3. 修正后的公式与量纲

候选集合V、要点集合C、请求容量K在一次选择开始前固定。对K>0：

```text
r_i in [0,1]                       supplied relevance
w_c >= 0, sum_c w_c = 1            normalized aspect weights
 g_ci in [0,1]                     supplied aspect support, fixed
m_c(S) = max_(i in S) g_ci         m_c(empty)=0
R_K(S) = sum_(i in S) r_i / K
C(S) = sum_c w_c * m_c(S)
F_K(S) = lambda * R_K(S) + (1-lambda) * C(S)
subject to S subset of V and |S| <= K, lambda in [0,1]
```

仅在可行集上，R_K、C和F_K的数学范围都是0–1。相比上次未归一化的sum r，容量5、lambda=.5时旧式最大3，相关性最大贡献2.5、覆盖最大贡献.5；新式两部分最大贡献均.5。这统一最大尺度，不承诺实际贡献总是各半，也不保证新权重更适合所有任务。

K必须是固定的请求容量，不能用当前|S|：当已有一条r=1、覆盖=.5的记忆时，lambda=.5得到.75；追加r=.1而没有新覆盖，按|S|平均变为.525，违反单调性。固定K=2则.5变为.525。也不采用min(K,候选数)，避免加入一个r=0/g=0的无贡献候选改变已有集合的目标值。候选不足时R_K较小，表示相对请求容量的已填贡献，不是记忆平均质量。

K=0只允许空集合，输出目标及两个分量均0，不执行除法；输入仍先做全部合法性校验。

每步计算：

```text
Delta(i | S) = lambda*r_i/K
              +(1-lambda)*sum_c w_c*max(0, g_ci-m_c(S))
choose unselected i with largest positive Delta
```

选择后更新m_c。达到K、无剩余候选或最大增益<=0时停止，不为了填满容量塞入零贡献项。候选输入顺序是调用方已有排序；完全相等的浮点增益用更早输入位置打破平局。近似相等不额外设epsilon，不用随机数或UUID文本字典序影响平局。

相关性来自显式r，不能直接把可能越界的RRF/BM25/余弦总分当r，也不在此模块按候选最大值自动重缩放。lambda首版建议默认.5，仅作为透明起点，允许显式传入0–1值；不在已用公开题上调整默认。

## 4. 数学性质与限制

固定K后相关性项是非负模块函数。给定固定非负支持矩阵，要点max的新增收益为max(0,g_ci-m_c)，随着S增长m_c不减，故新增收益不增且不负。非负加权合并后目标仍单调次模；归一化不破坏这些性质。

非负单调次模目标的纯条数约束，精确贪心有1-1/e代理目标近似界。[Krause与Golovin综述的facility location、非负组合和条数贪心定理](https://www.cs.cmu.edu/~dgolovin/papers/submodular_survey12.pdf)。此处是将定理条件核对到本方案的推导，不是原论文已经评测Mnemosis。界不保证真正必要证据找全或答对率，也不是全局最优声明；二进制浮点实现需单独验证数值误差。

反例：lambda=0、K=2，六个同权要点；A覆盖1/2/3/4，B覆盖1/2/5，C覆盖3/4/6。贪心先A，再B或C得到5/6；B+C达到1。测试应保留这个非最优案例。

如果真正任务需要B、C同时存在才有价值，任务收益可为f({B})=f({C})=0、f({B,C})=1，属于互补依赖，不能当次模覆盖。相关要点重复描述也会被多权重计入，需要独立要点定义；模块不自动证明要点独立。

不得把此界套用到token背包、任意冲突/实体兼容约束或必须成对的时间链。首版仅限制记录条数，实际文本token长度不相同，不能宣称同token成本。

## 5. 首版模块与接口契约

拟新增src/mnemosis/evidence_selection.py，直接从该模块导入；首版不改顶层__init__、MemoryEngine或现有recall签名。

```text
QueryAspect(aspect_id: str, weight: float = 1.0)
EvidenceCandidate(memory_id: str, relevance: float, support: Mapping[str,float])
select_evidence(candidates, aspects, *, limit: int = 5,
                relevance_weight: float = .5) -> EvidenceSelectionReport
```

输入采用只包含标识与分数的值对象。实现可用标准库dataclass；一次调用开始时复制/固化输入标量和映射，计算期间不改输入。仅当前调用局部缓存m_c，不建立全局缓存、状态哈希或数据库索引。

- candidates最多100条，aspects最多32个，limit是0–100的整数；超界拒绝，不能静默截断或扩展库扫描。bool不作为数值或整数参数接受。
- memory_id/aspect_id为非空、已去首尾空格字符串；各集合内标识唯一。重复ID拒绝，不按相同支持矩阵合并不同记忆。
- relevance、support与relevance_weight是有限实数且在0–1；非法值、NaN/Inf、负数和越界拒绝，不能靠截断掩盖来源错误。
- 原始要点权重是有限非负实数。非空aspects至少一个权重>0；先除以最大权重，再以math.fsum求和归一化，避免正权重直接相加溢出。零权重要点可报告，但不影响选择或计入未覆盖/部分覆盖清单。
- support中的未知aspect_id拒绝。缺少的合法要点支持按0参与代理计算，含义是“未提供支持”，不是证明该事实缺失。不得从金标/答案填支持；首版不自动从关键词或嵌入生成支持值。
- 空aspects只在relevance_weight=1时合法，作为显式纯相关性选择；其他值拒绝，避免悄悄构造虚假覆盖。空候选和合法非空aspects则返回空选择与全部正权重要点的0覆盖。
- 全部输入先校验，包括limit=0或空候选；格式/数值域错误ValueError，类型错误TypeError；不约定错误文案逐字匹配。

报告字段：selected_ids（贪心顺序）、steps、aspect_coverage（m_c）、normalized_aspect_weights、uncovered_aspect_ids（正权重且m=0）、partial_aspect_ids（正权重且0<m<1）、relevance_component（R_K）、coverage_component（C）、objective（F_K）、requested_limit、candidate_count。

每个step包括memory_id、relevance_gain（lambda*r_i/K）、coverage_gain（(1-lambda)*Delta C）、total_gain和objective_after。报告复制标量，不持有会被模块修改的记忆对象。未覆盖/部分覆盖只描述给定矩阵，不是对事实或回答充分性的确认；首版没有自动拒答阈值。

非负求和使用math.fsum。输出数学量的允许浮点误差为1e-12；仅最终0–1报告值允许消除此范围内的越界舍入。选择使用未做显示舍入的边际增益；不把负输入截断为0。数学界的验证采用独立Fraction小样本，不声称浮点执行严格达到精确理论界。

## 6. 数据流与后续集成边界

首版：调用方准备有界候选/要点/支持 → 完整校验与快照 → 归一化权重 → 逐步选择 → 返回解释报告。函数不读取数据库、检索日志、来源证据、反馈计数、访问次数或时钟；不生成新记忆/关联，也不调用模型。

调用方负责候选ID确实对应适用记录、过滤已回收/排除项、实体/情境/版本条件，以及独立提供支持的来源。函数自身没有记录正文或事实版本字段，无法替调用方判断真假、冲突、必要时间链。原始候选仍保留供下游审查；没有自动删库或合并。

未来接入recall必须在足量、有界候选产生后、TopK截断和final强化前进行，明确所有时间/实体锚点和只读开关。当前dual_track已在多处截取scored[:top_k]，retrieval_mixin还追加锚点并最终强化；先对旧Top5去重无法找回第6条。本设计不预先修改这些路径，也不直接扩大原候选预算。

未来是否接入或推广默认，需要另外审核真实查询支持生成、完整入口、历史回归、必要证据损失和延迟。首版数学接口通过不等于检索模块已经受益。

## 7. 提前固定的手算用例与验收

主要数学用例：lambda=.5/K=2，要点X/Y权重.6/.4。A相关1支持(1,0)；B相关.95支持(1,0)；C相关.4支持(0,1)。先选A；第二步旧未归一化B/C增益.475/.4，新式为.2375/.3，选C；新F({A,B})=.7875，F({A,C})=.85。是构造数学差异，不是公开任务质量收益。

实施获批后先写实际API失败测试，再最小实现：

1. 手算互补选择、重复支持饱和、改进同一要点支持和多要点同时增益；断言selected_ids与独立预期增益。
2. 容量0/1/5/大于候选数、空候选、零贡献、lambda=0/1、纯相关性空要点和确定性平局。
3. 相关性/支持/权重非法数值与类型、重复标识、未知要点、候选/要点预算；不以测试读取实现常量作为预期。
4. 正要点权重共同缩放不变，极大/极小正权重不过流；添加零贡献候选不改变已有集合目标。
5. 用独立Fraction穷举N<=8的固定矩阵验证0–1可行界、单调性、边际收益递减、目标分解与小样本贪心近似界；保留5/6非最优反例。预期计算不调用产品评分辅助函数。
6. 输入映射/记录不变；显式候选来自Dict/SQLite实际记忆样本时，全量记忆/链接/日志及SQLite只读诊断不变。两后端重复不算新增独立轨迹。
7. 完整既有测试与能力/生命周期门槛通过；保留旧默认和接口行为。数学选择器新增测试通过后才运行离线原TopK/精确重复记录对照，不把支持矩阵同形当事实去重。

首版仅报告这些构造数学用例及代理目标，另报实现的有界候选耗时；不使用148已看公开题调lambda，也不称新盲测。新真实检索评测必须先解决独立要点/支持来源，并在调规则前冻结独立会话。没有收益或出现必要证据损失时保留实验接口，原流程继续。
