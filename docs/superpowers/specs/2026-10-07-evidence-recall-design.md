## 接法比较与选择

| 接法 | 优点 | 限制 |
| --- | --- | --- |
| 调用方手工提供要点和支持 | 接口简单、可精确校验 | 不解决普通查询的自动输入问题，仅适合控制测试 |
| 本机模型标注，再引用核验及数学组合 | 能处理自然语言查询，可接入实际API和MCP | 增加推理成本，支持判断仍可能出错 |
| 把关键词或余弦直接当支持 | 成本低 | 混淆相关性与语义支持，容易让粗摘要假装完整 |

选择第二种，同时保留注入固定标注提供者用于确定性测试。第一种不冒充自动检索收益；第三种不作为支持判断。

## 首版交付与边界

新增可显式启用的MemoryEngine.recall_evidence及实验性同名MCP工具。真正串起已有召回、自动要点/支持标注、引用一致性检查与select_required_evidence，而不是再增加一个只处理外部候选的独立函数。

原recall及其MCP工具保持原签名、返回类型和默认行为。首版新入口只读，不强化候选、不写记忆、反馈、召回日志或工作记忆。未通过真实对照前，不切换默认工具。

首版不做自动回答、查询改写/补搜、学习新支持、事实可信度估计、冲突裁决或跨事件自动合并。不新增依赖，不下载新模型，不修改原检索评分和候选准入预算。

## 查询流程

1. 验证查询和参数，固定带时区的now。获取已有recall的实际结果，top_k使用candidate_limit，强制read_only=True。保留现有词形、准入、语义重排、时间、kind/context/exclude控制。
2. 将至多100个返回结果按原顺序冻结为快照：ID、完整正文及RecallResult所需字段。标注与返回基于同一快照；模型调用期间不持有引擎锁。默认candidate_limit=100，top_k=5。没有候选时直接返回not_applicable/empty_candidate_pool和空baseline，不调用模型或宣称已经完成证据证明。
3. baseline为该较大查询结果的前top_k条。它不等同于另一次recall(top_k=5)；评测必须另跑原查询，分离扩大返回池与数学选择的影响。
4. 从问题本身生成要点和适用范围。此阶段不提供候选正文、测试答案或gold证据。程序按输出顺序生成a0等ID，最多8项，描述长度不超过512码点。首版自动要点等权、全部必需、阈值1；不让模型调效用权重或输出概率。
5. 分批提供问题、固定要点、候选ID与原文，要求逐候选/要点输出supported、not_supported或unknown。supported必须附原文逐字引用；其它两种不得附伪证据。只要求判断支持，不生成答案。
6. 从引用在本条原文中的唯一精确出现位置计算Python Unicode码点偏移。不存在或多处出现时拒绝该批标注，不自动规范化、换绑候选、修补引用或补成1。复用现有引用校验规则检查绑定。
7. supported转为1，明确not_supported转为0，unknown或未返回保留缺失。模型判定只表示标注来源，逐字匹配不能证明语义蕴含。
8. 将原返回排序作为单通道，复用已有排名相关性定义r_i=61/(60+rank_i)。这仅向选择器提供有界输入，不覆盖原RecallResult.score，也不增加排名通道/总分权重。
9. 调用原select_required_evidence：固定容量U、relevance_weight默认0.5、search_budget默认10000，原始精度阈值比较及求解状态保持原义。
10. 将选中的ID映射回冻结的RecallResult快照，并一起返回标注/数学诊断。没有可行组合时不把baseline冒充完整组合。

## 适用范围和输入完整性

首版处理能从问题明确拆成有限证据职责的事实查询、明确两对象比较、明确前后事件查询。要点应表达实体、事件和所需角色；不能把泛泛主题当作多项具体证据的替代。

开放集合枚举或未知数量聚合不能从问题确定完整的所需集合。带明显“所有/全部/哪些/all/every”等开放范围标记的查询先保守报告not_applicable；提供者也须输出finite、open_set或unsupported。不得把一个“有哪些事件”大要点被单条记忆支持，包装成已经列全全部事件。此限制会影响部分公开题，必须计入全题结果，不删除不适用题。

没有要点或被判不适用时，返回baseline及明确原因，selector=None。标注提供者把问题误判有限的风险仍存在，验收中必须包括开放集合、否定、同名、历史版本、事件顺序和粗摘要反例。

输入原文可能包含指令，作为数据处理，不允许改变标注协议或调用工具。提供者没有文件、存储写入、外部工具或其他会话能力。

## 资源预算

| 项目 | 首版边界 |
| --- | --- |
| query | 非空，最多4096码点 |
| top_k | 非bool整数，1–100，且不超过candidate_limit |
| candidate_limit | 非bool整数，1–100，默认100 |
| 自动要点 | 最多8项，每描述512码点；数学接口原32项边界不改 |
| 单条可标注正文 | 最多2048码点；超长记录不截断，整条保留unknown并报告跳过 |
| 支持分批 | 1–8条原文/批、最多13批，完整问题及要点每批固定 |
| 提示大小 | 每次完整messages序列化的UTF-8最多12288字节；动态缩小批次，单条仍放不下则跳过并报告 |
| 模型输出 | 结构化JSON；支持批最多64决策；读取响应最多1MiB |
| 模型生成 | 非流式，temperature=0，num_ctx=16384，单次num_predict=2048 |
| 请求预算 | 1次要点＋最多13次支持；每次socket timeout最多10秒，全流程模型预算60秒，不重试 |
| 数学预算 | 0–100000节点，默认10000，沿用已实现规则 |

60秒为发起下一次请求前检查的截止预算，不宣称能强制中断任何已启动的本机推理。每次请求使用剩余预算与10秒两者较小值；记录实际耗时、超时和未标注批次。非流式返回不做无界读取。短输入也可能超过模型上下文或输出上限，响应不完整时按缺失/失败处理，不能当作全部不支持。

提示字节边界用于保守控制负载，不当作精确token计算。本机模型元数据qwen2.context_length=32768，16384配置在其范围内；实际prompt_eval_count/输出截断信息另行记录，发现异常则拒绝该批。不能保证检测所有模型静默截断。问题/要点单独已超提示预算时为annotation_failed，不悄悄删除要点。

超长、未完成批次、unknown、缺行和非法批次都保持独立原因与数量。13批不足以覆盖全部动态小批次时，剩余记录保持unknown。明确0只表示给定正文上的模型判断，不证明真实事实不存在。禁止静默丢弃候选后改变相关性排名或缩小原容量分母。

## 接口与报告

新入口参数包含query、annotator、top_k、candidate_limit、relevance_weight、search_budget，以及kind、now、context、exclude_ids、temporal_policy、lexical_policy、candidate_policy、rerank_policy。annotator在Python API显式传入；未配置时在查询前报参数错误。第一版只读，因此不接受read_only=False或learning_policy。

报告包含：baseline、candidate_ids、selected results、aspect descriptions、annotation_status、annotation_errors/skipped IDs、逐字引用、rank relevance、RequiredEvidenceReport及各阶段耗时。保留原confident字段原义，不能拿它代替支持正确性或答案完整性。

顶层status约定：

| status | results与含义 |
| --- | --- |
| feasible | 返回已选快照；只表示给定标注下满足约束，标注状态另列 |
| infeasible | 空selected results；给定候选/有效支持下数学不可行 |
| undetermined | 空selected results；求解预算结束，未找到可行组合 |
| annotation_failed | 要点响应非法，或非空池没有任何有效supported/not_supported决策；baseline单独保留 |
| not_applicable | 返回baseline；没有启用数学约束，明确原因 |

支持部分缺失但存在有效组合，可以返回feasible，并且annotation_status=partial；不把部分标注说成全库已评估。合法完整标注全部0时允许返回infeasible，并标明model-annotated inputs。可行但搜索未完成仍是optimality=not_proven。

原selector.completeness保持精确Fraction。MCP用显式分子/分母或字符串序列化精确字段，不从显示浮点重新判断达标。异常配置、非法kind/policy、超限等在检索/模型请求前拒绝。

## 本机标注提供者与MCP

提供者接口分为question-only plan与batched support两步，可注入固定响应用于测试。Ollama实现只用标准库HTTP访问本机/api/chat，JSON schema与结果的程序验证双重检查。官方接口支持format传JSON schema，但结构约束不验证语义：[Ollama结构化输出文档](https://docs.ollama.com/capabilities/structured-outputs)。

模型名、服务地址及请求预算由运行者配置，不接受记忆文本或MCP请求改写服务地址/模型。默认服务http://127.0.0.1:11434，模型qwen2.5:3b；配置显式启用，不影响原embedder。

MCP新增recall_evidence至EXPERIMENTAL_TOOLS，使用现有注册/处理器机制；core/advanced的列表不新增此工具。使用--expose experimental并显式配置evidence annotator才可调用自动路径。新增server参数--evidence-annotator none|ollama、--evidence-model、--evidence-base-url；默认none。stdio与HTTP配置一致，不额外启动服务或联网安装。旧recall不因此变成模型调用。

2. B：原recall(top_k=100)的前5，分离扩大候选输出的影响。
