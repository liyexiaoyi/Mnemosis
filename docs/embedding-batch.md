# 本地 NGram 批量嵌入优化

`NGramEmbedder.embed_many(list_of_texts)` 在一批至少两条文本中复用重复特征的 BLAKE2b 地址/符号计算。单条 `embed` 保留原实现；没有新依赖、网络调用或模型替换。

缓存只属于本次调用，最多 8192 项，单项特征最多 256 个 Unicode 字符；超过限制仍正常计算，只是不入缓存。只缓存原始地址与符号，每次按当前维度取模；特征顺序、次数、权重、浮点累加和归一化不改变。批次结束后不在实例、全局或磁盘保留词法特征；调用方原有文本/输出列表不属于此缓存。

自定义子类/实例/类级 `embed` 替换继续逐条分派；`features` 子类覆盖仍生效。空列表、单条、列表以外的可迭代输入继续既有路径。两条特征重叠少的多样性输入，本机实测约慢0.125ms；并非所有文本都保证提速。若主要处理这种微批次，可继续逐条调用原scalar embed。

保持两个热点循环（scalar 和 batch），避免单条路径每个特征增加缓存分支；冻结旧实现及边界测试防止分叉语义。以后改权重/归一化必须同时维护两条路径并更新明确的兼容契约。

```python
from mnemosis.embedding import NGramEmbedder
embedder = NGramEmbedder(dimension=256)
vectors = embedder.embed_many(["喜欢本地记忆检索", "本地记忆需要来源证据"])
```

本轮改动只是减少确定性重复计算，缓存不是记忆证据、熟悉度或强化状态。外部模型嵌入器的请求/重试/缓存策略未改变。

完整导入对照：`benchmarks/embedding_ingest_eval.py --baseline <可信旧源码 ZIP> --output <新输出目录>`，默认七轮交替。SQLite 记忆库与向量库从空库开始，1000 条分批、关闭自动线索/情境、无联想边；计时包含原生 SQL 写入和向量投影，建库/快照/关闭不计时，缓存每批重新创建。默认首尾轮次全量核验持久记忆、向量与桶，中间轮次核对行数与固定样本；返回顺序及精确/LSH 查询每轮比较。需要每轮完整持久状态对照时传 `--verification full`，详见 [评测验证说明](evaluation-verification.md)。只测合成负载，不表示真实 agent 回答质量、所有导入方式或跨平台收益。
