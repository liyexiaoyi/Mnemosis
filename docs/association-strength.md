# 可选联想强度折扣

在现有 `MemoryEngine.recall` 或 `DualTrackStore.recall` 中显式启用：

```python
results = engine.recall(
    "coral research",
    association_policy="weighted",
    lexical_policy="inflection",  # 可以与已有词形策略组合
    read_only=True,
    top_k=5,
)
```

默认 `association_policy="legacy"` 保留原来的联想加分。此选项目前仅暴露在以上两个召回入口；`recall_fused`、CLI、MCP工具及其他高层辅助入口不因此自动启用。

原来的一跳扩散按根节点分数、扩散折扣和邻居写入序号距离排序后的名次给关联记忆加分，没有读取存储的关系强度。可选策略在该分数上乘以 `min(1.0, weight)`，只接受有限且大于0的权重；零、负数、NaN、无穷值不通过此扩散通道激活邻居。大于1的强度饱和到1，避免熟悉度放大为无限加分。

保持原来的最多5个扩散根、每根最多50个参与扩散的邻居；每根仍从既有 `related(depth=1, max_nodes=1000)` 池按写入序号距离选择。零权重邻居占据原来的选择位置，不补取预算外邻居。默认参数下一次查询最多增加250次现有索引上的关系权重读取，不建立新索引，也不扩大图深度、词法100候选或默认语义64重排预算。高连接度图可能有额外数据库读取开销，不能当作性能加速。

已有直接匹配分数只会在联想分数更高时被替换，不因弱关系而降低。多个根指向同一邻居时沿用最大激活分数，不叠加为独立证据。返回的加分原因标为 `weighted association; relevance only`。

关系强度是相关性线索，不等于真实、来源可信度、事实有效期或独立证据。此策略不改变 `evidence_count`、来源、已验证成功，也不改变建图、模式补全、事件链、其他约束与反馈规则；记忆仍可能通过词法、时间链或模式补全等其他通道出现。`read_only=True` 保持所有持久记忆、关系和日志。既有 `learning_policy="final"` 仍只强化最终返回的原始词法匹配，不把纯联想当作任务已验证有效。

弱关系有时确实连接必要证据，降低加分可能使它被直接候选挤掉。原来被邻居预算截掉的强关系不会因本选项自动回到池中；缺少关系的多证据问题也不会自动解决。普通共享线索创建的1.0关系仍保留原加分，它们是否真正相关需要单独改进建图。因此先显式启用，不全局切换默认。

本轮评测区分预先固定的构造图案例、既有公开题回归与查询开销。构造案例不是真实任务样本，公开回归不是新的盲测；参见E盘第十七批报告。
