# 冷建分词优化与复测

现有 tokenize 的输出语义保留：Unicode lower、停用词、复合词、中文/数字日期、中文数词单位、CJK单字/双字、顺序与重复次数不变。动态 ZH_DATE_NORMALIZE、STOPWORDS、CJK_STOPWORDS 继续生效。

固定正则在导入时编译。没有 '-' 或 '_' 的文本跳过两次复合词扫描；没有 '年' 的文本跳过中文日期扫描/移除。普通正文由8次原生正则调用减至3次。保留已有 Python Unicode 与正则实现；本轮没有新 Rust 分词器或持久词项缓存，也没有存储迁移。

这会改善首次建立 BM25 倒排索引，以及其他真实调用分词器的路径。日期/复合词密集文本收益较小；不同内容比例会改变收益。用户无需新开关，原有 Python/Rust BM25 选择照常使用。

## 冻结语义和验证

`tests/fixtures/tokenize_a2199c2.py` 是提交 a2199c2 的历史参考，不随优化更新。其函数/配置 AST 与修改前 Git 档案完全相同，专用 -text 属性保持档案字节校验稳定。测试检查词项列表逐项一致，包含重复与顺序；覆盖中英文、Unicode扩展、非法日期、金额/单位、相邻及重复日期、日期开关和动态停用词，并用固定随机种子生成组合输入。

保留原有规则也保留其局限。例如中文金额的百/千等形式并非都被当前正则识别；不能把“与旧版一致”称作这些格式已修复，相关质量改进需另做评测。本批不更改其词项规则。

## 同数据性能对照

```text
python benchmarks/cold_bm25_eval.py --database <既有合成库.sqlite> --output <新结果目录>
```

脚本在同一 BM25 模块内交替使用冻结旧函数与当前函数，其他引擎、原生二进制、数据库、参数都相同。每种内核至少七轮、前后顺序交替；包含全库读取、分词、Counter、索引构建、查询及最终对象读取。旧索引释放放在计时外，避免把上一份缓存销毁算给下一次建索引。

这是应用缓存冷建，操作系统缓存/背景负载不受控，不是进程首次启动或磁盘冷启动。状态哈希和结果签名检查保证只读及相同排名/分数/理由/置信标志。针对刚建完索引的热查询波动，还用同一份固定索引另做21轮配对；原生哈希布局不同造成的波动不应自动归因分词变化。

内存观测提供进程工作集、峰值工作集及进程提交量。独立进程仅保留一份Rust索引，但数字仍包含Python、SQLite和分配器保留；不是精确Rust堆占用。本轮不能声称内存下降，也不能把此速度收益称作检索准确率提升。
